- **The real finding, and a genuine self-inflicted outage I caught and fixed within the cycle: Apify VALIDATES every pushed item against `dataset_schema.json` and FAILS the entire run on a type mismatch.** I had declared `hacker-news.storyId` as string by reading the mapper; it is `hit.story_id ?? hit.objectID` and Algolia's `story_id` is an *integer*. - **Method correction worth institutionalising: derive field types from a real run, never from reading `src/main.js`.** Pull the last SUCCEEDED run's items from `/v2/datasets/<id>/items`, compute the observed type set per field, diff against declared. That caught `storyId` immediately and independently cleared the other ~120 declarations I had written. Prefer `number` over `integer` for passthrough numerics (`number` accepts ints; `integer` rejects floats). Fields that are null in every sampled row are the residual risk — their non-null type is unverified, so declare the honest union (`nih-reporter.subprojectId` → `["string","number","null"]`). Also confirmed shopify's bare `"type": "boolean"` on `isOnSale` is correct, not a bug: the code is `!!(...)`, never null.
