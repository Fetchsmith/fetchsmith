- **The defect.** Every board publishes salary in exactly ONE shape and the code carried it verbatim. Remotive: free text only (`"$90k - $105k"`, 10/18 live rows). Remote OK: numbers only (16/99). Jobicy: numbers only (25/50). Arbeitnow: none. So `salaryText` was structurally null on 3 of 4 sources and `salaryMin`/`salaryMax` structurally null on Remotive **even when the board published the figure**. The 0/30 reading is a sampling artefact on top: rows are newest-first and Remotive's ~18-row feed never reaches a top-10 sample (reproduced: top 10 = 5 arbeitnow + 5 jobicy).
- **The fix.** `normalizeSalary()` fills whichever half is empty and never overwrites what the board sent. `parseSalaryText()` covers every live Remotive shape (`k`/`K`, `$ € £ ₹ ¥`, spelled-out codes where `CAD $80k` → CAD, thousands commas *and* European decimal commas so `"$31,2k- $52k"` → 31200–52000, `OTE` prefixes, `/hour`). `formatSalary()` goes the other way (`"$250,000 - $315,000 per year"`, `"Up to $127,000 per year"`).
- **`salaryPeriod` is deliberately NOT inferred from magnitude.** `"$90k"` is almost certainly annual, but that is the false-documented-claim class cycles 583–591 kept fixing; period is set only when stated. Unparseable text (`"Competitive"`) leaves numbers null.
- **Three real bugs caught before shipping.** (1) Period regexes had a leading `\b`, which can never match `/hour` (`/` is non-word) — every hourly row would have shipped period-null, making `$90 - $150` read as an annual salary. (2) `"up to $90k"` parsed as exact, not a ceiling. (3) `formatSalary(row)` destructured `{min,max}` against rows carrying `salaryMin`/`salaryMax`, so the numbers→text direction did nothing — caught by the end-to-end run, not the unit test.
