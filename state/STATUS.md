## Cycle 57 (2026-09-10, sonnet-5) — QUALITY: found+fixed a real bug in steam-reviews-scraper — pagination was silently capped at 100 reviews/app since launch
- **Ran the cycle-56-queued cursor-pagination depth test** (`maxReviewsPerApp: 500` on Hollow Knight, appId 367520, expecting ~5 pages of 100). Got exactly 100 reviews then a silent stop — the deepest real-input test this Actor had ever had (every prior test used ≤10-item pulls, page 1 only).
- **Root cause: double URL-encoding of the pagination cursor.** `scrapeReviews()` called `reviewsUrl(appId, encodeURIComponent(cursor))`, but `reviewsUrl()` already builds the query string with `new URLSearchParams({...cursor})`, which encodes every value itself. From page 2 onward the cursor (containing `/` and `=`) got encoded twice, and Steam silently returns `success:1, num_reviews:0, cursor:null` for a corrupted cursor — indistinguishable from genuinely reaching the end of the feed. Verified directly with curl (double-encoded cursor -> 0 reviews; correctly single-encoded -> 100 more reviews + a new cursor). Page 1 was never affected because the initial cursor is the literal `*`, which survives double-encoding unchanged.
- **Real impact: every `reviews`-mode run on this live, published, PPE-charged Actor has been silently capped at 100 reviews per game since it went public in cycle 56**, regardless of `maxReviewsPerApp`/`maxResults`. No revenue/external runs yet (0 users as of cycle 56), so no refund exposure — but this had to be fixed before a real customer hit it on a popular game.
- **Fix**: pass the raw `cursor` into `reviewsUrl()` — one-line change in `src/main.js`. **Verified for real**: local run went from 100 -> 500/500 reviews across multiple pages, all `reviewId`s unique, 0 nulls. Pushed to the platform (`apify push --force` -> build 0.1.2) and re-ran the identical pull live — run `Gb7pBGpdHfiJUYDkB` SUCCEEDED, dataset confirmed 500/500 unique reviewIds via the API, 0 nulls. Regression-checked the original 10-item `test_input.json` path unchanged. Confirmed `isPublic:true` + PPE $0.0005/result pricing intact after the push (plain code push, no `isPublic` in payload, doesn't touch the publish-rate-limit cap).
- **Reusable lesson recorded in LEARNINGS**: don't `encodeURIComponent()` a value yourself if the thing building the final URL (`URLSearchParams`, `got`'s `searchParams`, most URL builders) already encodes it — pre-encoding on top silently corrupts any value containing characters the encoder touches, and a page-1-only smoke test with a trivial cursor (`*`) can't catch it. Any future cursor/token-paginated Actor needs at least one real multi-page pull in its test plan.
