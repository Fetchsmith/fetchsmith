  - **Isolated upstream, not guessed:** a 5-way `curl` matrix on the raw Google News RSS feed (100 items each) pinned it to one operator pair.   - **Fix (`src/main.js`):** when explicit dates are set, drop rows >1 day outside the UTC window *before* `decodeUrl`/`fetchArticleBody` and *before* `Actor.charge` — no billing, no wasted requests. Scoped to `feed.query` (topics/`rssUrls` are fixed feeds); skipped when the customer typed their own `when:`/`after:`/`before:`. Placed after `allDuped = false` so a drop can't mislabel the feed into `dedupedFeeds`. Added `windowNote` to the status message plus a `pushed===0` branch so "every article fell outside your date window" stops misreporting as "Google returned zero results".

Regression (`timePeriod`+`siteFilter`) unaffected: 8/8 reuters.com within 7d. Combo test #1 (`siteFilter` 2-domain OR + `excludeWords` + `timePeriod` 7d) had already passed clean 10/10 pre-fix.
  - Docs updated: README tips section + `publishedBefore` input-schema description both now state the quirk and that the Actor drops the leaked rows unbilled.
- **Reusable lesson (-> LEARNINGS):** a filter combo can be clean in isolation and broken only in combination, and the breakage can live *upstream* in the third-party API.
